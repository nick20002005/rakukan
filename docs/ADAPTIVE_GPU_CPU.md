# GPU/CPU 自動選択

[general] の adaptive_gpu = true で有効になります。既定は false です。
n_gpu_layers = 0 の場合は常にCPUのみで、追加モデルを作りません。
変更はengine再起動で反映します。ABIとRPCプロトコル番号は変更しません。

有効時は同じモデルをGPU設定とCPU設定で各1個ロードします。
同じconverterが両モデルと計測状態を所有するため、BGへのtake/setで
状態が失われません。engine_reload_forceでは両モデルと状態を作り直します。
推論エラーは握りつぶさず既存の復旧経路へ返します。

判定対象は成功した生成処理のms/読み文字数です。greedyと各beam幅は
別々に計測し、係数0.5の指数移動平均を保持します。
最初はGPUを使い、3件成功後にCPUで1件処理して基準値を得ます。
以降は主デバイス8件につき他方を1件試し、回復と基準値を更新します。
プローブも通常のリクエストを処理し、二重推論やモデル再ロードはしません。

GPU平均がCPU平均の1.30倍を超えた状態を2回観測するとCPUへ切り替えます。
GPUへの復帰はGPUプローブで0.85倍未満を2回観測したときです。
境界を満たさない計測で連続判定をリセットします。
空の読み・モデルを使わない連打入力・失敗した推論は計測に含めません。
切替時はINFOに方向・両平均値・復号幅を記録します。
beam/greedy完了ログには実行デバイスを記録します。

読み以外の文脈長・生成長・CPU競合による時間差は残るため、
実機負荷下で閾値とプローブ間隔の妥当性を評価する必要があります。
GPU呼出し自体がハングする場合は従来どおりwatchdogによる復旧が必要です。
